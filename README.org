#+title: jazz

some daisy seed effect pedal firmware

run ~nix-shell~ to get dependencies. see [[https://github.com/glittershark/jazz/blob/main/shell.nix][shell.nix]] for a list of dependencies if
you are less of a nix weenie than i am

* building and testing

be sure to check out all the submodules:
#+begin_src shell-session
$ git submodule update --init --recursive
#+end_src


to build firmware blobs for all effects:

#+begin_src shell-session
$ make
#+end_src

to run tests:

#+begin_src shell-session
$ make test
#+end_src

~compile_commands.json~ is automatically merged from both ARM and host builds into the project root for clangd/language server support.

* host audio CLI

for quick iteration without flashing firmware, the host CLI lets you run effects
on mp3 files from your computer.

** quick start

build the host CLI:

#+begin_src shell-session
$ make console
#+end_src

run input through the default effect (~granular~) and play through your computer:

#+begin_src shell-session
$ ./build-test/src/console/jazz-console input.mp3
#+end_src

save processed output to a new mp3:

#+begin_src shell-session
$ ./build-test/src/console/jazz-console input.mp3 --output processed.mp3
#+end_src

output filenames default to the ~mp3s/~ folder in the current directory (created
if needed), so this writes ~mp3s/processed.mp3~ when run from the repo root.
explicit paths such as ~./processed.mp3~ or ~/tmp/processed.mp3~ are used as given.

if playback fails on your machine, disable playback and render offline:

#+begin_src shell-session
$ ./build-test/src/console/jazz-console input.mp3 --no-play --output processed.mp3
#+end_src

** effects and chains

list available effects:

#+begin_src shell-session
$ ./build-test/src/console/jazz-console --list-effects
#+end_src

select one effect:

#+begin_src shell-session
$ ./build-test/src/console/jazz-console input.mp3 --effect clip
#+end_src

try the fridge terminal preset:

#+begin_src shell-session
$ ./build-test/src/console/jazz-console input.mp3 --preset presets/host/fridge_demo.toml --output fridge_demo.mp3
#+end_src

try the standalone la sort demo (the same sorting engine runs on the Daisy):

#+begin_src shell-session
$ ./build-test/src/console/jazz-console input.mp3 --preset presets/host/la_sort_demo.toml --output la_sort_demo.mp3
#+end_src

add ~--no-play~ to render offline. for a fully wet version or a different rank:

#+begin_src shell-session
$ ./build-test/src/console/jazz-console input.mp3 --preset presets/host/la_sort_demo.toml --la-sort-dry 0 --la-sort-wet 1 --la-sort-weight-center 0.65
#+end_src

la sort keeps the MP3's left and right channels separate. see
[[file:src/la_sort/README.md][the la sort guide]] for controls and firmware details.

inspect the fridge preset's LFO motion without rendering audio:

#+begin_src shell-session
$ ./build-test/src/console/jazz-console --preset presets/host/fridge_demo.toml --fridge-lfo-chart
#+end_src

render that LFO motion as a matplotlib image:

#+begin_src shell-session
$ python scripts/plot_fridge_lfo.py --preset presets/host/fridge_demo.toml --output fridge_lfo.png
#+end_src

chain multiple effects in order:

#+begin_src shell-session
$ ./build-test/src/console/jazz-console input.mp3 --effect clip,lowpass,granular
#+end_src

** effect parameters

you can tune parameters from the command line:

#+begin_src shell-session
$ ./build-test/src/console/jazz-console input.mp3 --effect clip,la_sort --clip-threshold 0.2 --la-sort-weight-center 0.65
#+end_src

supported parameter flags:
- ~--clip-threshold~, ~--clip-gain~
- ~--anticlip-threshold~, ~--anticlip-gain~
- ~--lowpass-alpha~, ~--highpass-alpha~
- ~--cursed-lowpass-alpha~, ~--cursed-highpass-alpha~
- ~--la-sort-weight-center~, ~--la-sort-weight-sharpness~
- ~--la-sort-dry~, ~--la-sort-wet~
- ~--la-sort-length~: integer 1–1024 samples, default 64; preset key ~la_sort_length~
- ~--la-sort-volume-compensation~: 0–1, default 1; fixed sqrt(length) wet gain, up to +30 dB at 1024 (no dynamics control)
- ~--la-sort-lfo-rate~: 0.05–20 Hz, default 1; ~--la-sort-lfo-depth~: 0–1, default 0 (off), 1 sweeps the whole list

the fridge effect is configured through preset keys with the prefixes
~fridge_head_N_~ and ~fridge_lfo_N_~; see ~presets/host/fridge_demo.toml~.

** presets (toml/json)

load a preset file:

#+begin_src shell-session
$ ./build-test/src/console/jazz-console input.mp3 --preset presets/host/clip_lasort.toml --output processed.mp3
#+end_src

example presets included in repo:
- ~presets/host/fridge_demo.toml~
- ~presets/host/la_sort_demo.toml~
- ~presets/host/clip_lasort.toml~

CLI flags override preset values, so you can start from a preset and tweak:

#+begin_src shell-session
$ ./build-test/src/console/jazz-console input.mp3 --preset presets/host/clip_lasort.toml --clip-threshold 0.1
#+end_src

JSON preset example:

#+begin_src shell-session
$ cat > /tmp/example_preset.json <<'EOF'
{
  "effect_chain": ["clip", "la_sort", "highpass"],
  "clip_threshold": 0.3,
  "clip_gain": 10.0,
  "la_sort_weight_center": 0.62,
  "la_sort_weight_sharpness": 4.0,
  "highpass_alpha": 0.2
}
EOF
$ ./build-test/src/console/jazz-console input.mp3 --preset /tmp/example_preset.json --output processed.mp3
#+end_src

the CLI depends on ~ffmpeg~ and ~ffplay~ being available in your shell.

* flashing to daisy seed

to flash a particular effect to a daisy seed via STLink:

#+begin_src shell-session
$ make flash DIR=delay
#+end_src

or manually:

#+begin_src shell-session
$ st-flash write build/src/delay/delay.bin 0x08000000
$ st-flash reset
#+end_src

* current effects

** delays
- [[https://github.com/glittershark/jazz/blob/main/src/delay/delay.cpp][delay]]: literally just a perfectly clean delay.
- [[https://github.com/glittershark/jazz/blob/main/src/reverse/reverse.cpp][reverse]]: a simple reverse delay.
- [[https://github.com/glittershark/jazz/blob/main/src/granular/granular.cpp][granular]]: weird semi-generative granular delay.
- [[https://github.com/glittershark/jazz/tree/main/src/rachel][rachel]]: heavily modulated multi-delay

** filters
- [[https://github.com/glittershark/jazz/blob/main/src/low_pass_filter/lowpass_filter.cpp][low_pass_filter]]: simple one-pole lowpass filter.
- [[https://github.com/glittershark/jazz/blob/main/src/high_pass_filter/highpass_filter.cpp][high_pass_filter]]: simple one-pole highpass filter.
- [[https://github.com/glittershark/jazz/blob/main/src/cursed_low_pass_filter/cursed_lowpass_filter.cpp][cursed_low_pass_filter]]: cursed lowpass filter using exponentiation and multiplication.
- [[https://github.com/glittershark/jazz/blob/main/src/cursed_high_pass_filter/cursed_highpass_filter.cpp][cursed_high_pass_filter]]: cursed highpass filter using exponentiation and multiplication.

** distortion
- [[https://github.com/glittershark/jazz/blob/main/src/clip/clip.cpp][clip]]: hard clipping distortion.
- [[https://github.com/glittershark/jazz/blob/main/src/anticlip/anticlip.cpp][anticlip]]: adds back the residue from clipping.

** other
- [[file:src/la_sort/README.md][la_sort]]: stereo sorting-based effect with a weighted tap from a configurable rolling window (default 64 samples), shared by firmware and the MP3 demo.
